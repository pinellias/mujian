# 幕间 · 剧本写作工作台

## 项目介绍

幕间是一个「剧本写作工作台」：浏览器里写完即存、多设备共用一份、自家服务器托管、不依赖任何第三方账号。

<img width="1920" height="1080" alt="界面预览" src="https://github.com/user-attachments/assets/95755418-67e5-4f26-9afe-3daf560e3888" />


### 1. 剧本编辑器（Markdown 源码 + 实时预览）
- **源码编辑区**直接写 Markdown：任何文本编辑器都能直接打开 `.md` 文件读改，数据不被锁死。
- **预览排版**：点工具栏「预览」把源码实时渲染成剧本版式——角色居中、对白缩进、括注弱化，用来校对格式而不改文稿本身。
- **自动排版**：一键「自动排版」整理缩进与换行，省去手调。

### 2. 主题与外观
- 内置 4 套主题：**paper（米纸）**、**white（白）**、**mist（雾灰）**、**ink（深墨）**，点击即可切换，偏好自动记住。
- **正文字体 / 字号**：可换字体、调正文 `14~32px` 的字号。
- 左下角「大纲」实时解析 `###` 场景行，点击任一场景**直接跳转**到对应位置。
- 状态栏实时统计：正文**字数**（不计图片地址、不计标记符号）、**行数**、以及 `###` 解析出的**场数**，写作进度一目了然。

### 3. 多剧本管理
- 左侧「我的剧本」列表支持多剧本**标签页**切换；切换剧本后**自动记住滚动位置与光标**，切回原样停在原处。
- 剧本右键：重命名、向上 / 向下移动、**移到组 / 移出组**。
- **分组（文件夹）**：可建组把同一部剧的几集收在一起；组可展开 / 收起（收起状态记住），组上右键：新建剧本、重命名、删除组。

### 4. 导入 / 导出 / 备份
- **导入剧本**：支持 `.md`（源码原样进编辑区）与 `.txt`（自动转成 Markdown 结构）。
- **粘贴文本**：工具栏「粘贴文本」一键把剪贴板内容粘进当前编辑区（也兼容 `.txt` → Markdown 解析）。
- **备份包**：「我的剧本」右上角可导出全部剧本为 `.zip`（每篇一个 `.md` + 分组清单），导入备份包可整体恢复、同名覆盖、其余保留。

### 5. 显示大小
- 右下角 `− 100% ＋` 控制**显示比例 50%~200%**。
- 与工具栏 `A-`/`A+` 分工明确：前者看、后者写，两者相乘即屏幕实际大小。

### 6. 本地存储 + 云端同步
- **云端**＝在「云端设置」里填的那台服务器地址，只作为后台同步目标（填了就让本机和它双向对账）；留空＝只在自己这台服务器上，不与任何云端同步。
- **本机为主存储**：所有读写先落打开页面的那台服务器 `data/`，数据始终在你自己手里。
- **自动同步**：保存成功、窗口重新聚焦、断网恢复、页面重新可见时，都会自动把本机改动推给云端、并把云端新内容拉回本机。
- **手动同步**：想立刻对账就点一下 ⟳。
- **多设备共用**：在「云端设置」填同一台服务器地址，多台设备看的是同一份数据；浏览器本地还留一份 IndexedDB 后路，断网也不丢。

### 7. 访问口令（可选）
- 服务端用 `ACCESS_KEY` 环境变量做接口鉴权：设了口令，别人打开页面需先输入才能读写；页面本身公开，只有数据接口受保护。详见下方部署与「改访问口令」。

## 部署包结构

```
mujian/                        # 项目目录（自己命名，例如 /www/wwwroot/mujian）
├── server.js           # 后端服务（Node 原生，零依赖）
├── console/            # 前端页面（无需改任何配置）
│   ├── index.html      # 页面骨架
│   ├── style.css       # 全部样式
│   ├── app.js          # 全部页面逻辑
│   └── boot.js         # 开页先套主题/字体/字号，防刷新闪一下（必须早于 app.js）
├── data/               # 剧本数据目录（每个剧本一个文件，自动生成）
│   ├── 我的剧本.md …    # 每个剧本一个文件，frontmatter 记元信息
│   ├── .groups.json    # 分组
│   ├── .order.txt      # 剧本排列顺序
│   └── .deleted.json   # 删除墓碑（同步用：记录哪篇在什么时候被删过）
└── deploy/
    └── install-service.sh   # systemd 服务安装脚本（自动探测 node / 项目目录，见下方）
```

> 改样式只动 `style.css`、改逻辑只动 `app.js`。`boot.js` 单独留着是有意的：它很小，放在 `<head>` 里同步执行，在页面渲染前就把背景色、字体、字号套上；如果并进 `app.js`，就得等大文件下载完才上色，刷新时会先闪一下默认样式。

双向对账规则（本机 ⇄ 云端，按「最后改到几点」）：

| 情形 | 结果 |
|---|---|
| 两边都有、时间不同 | 时间戳新的赢 |
| 一边有、另一边没有 | 直接复制过去（不含墓碑时） |
| 一边有、另一边是墓碑 | 比时间：删除晚→一起删；那边反而改过→拉回来保留 |
| 两边都是墓碑、或时间戳相同 | 不动，重复点不会白写一遍 |

分组数据单独存放在 `data/.groups.json`，格式为 `{ groups:[{id,name,open}], docs:{ 剧本名: 组id } }`——改动很小，可以直接用文本编辑器改。改名、删除剧本、删除组都会自动同步这份映射。

> 服务端本来就允许跨域（`Access-Control-Allow-Origin: *`），所以本机页面直连另一台机器不会被浏览器拦。切换地址时，浏览器本地副本里已有的稿子会按最新日期合并过去，不会凭空丢东西。

## 云服务器部署指南（systemd）

用 systemd 把服务托管成后台守护进程——开机自启、崩溃自动重启、有标准日志（`journalctl`）。服务起来后用 IP + 端口直接访问，不需要域名。

### 1. 准备项目目录 & 安装 Node.js

把整个项目目录（含 `server.js`、`console/`、`data/`、`deploy/`）传到服务器，例如 `/www/wwwroot/mujian/`。

Node 要求：本项目是 Node 原生零依赖，只用到 `http` / `fs` / `path` / `URL` 等核心 API，**Node 8 都能跑**，新版本随意。
- 宝塔装的话：宝塔「软件商店 → Node.js 版本管理器」里选一个版本，装完在 `/www/server/nodejs/` 下就能找到 `node`。

### 2. 运行安装脚本（自动建好 systemd 服务）

`deploy/install-service.sh` 会**自动探测 node 路径（含宝塔 `/www/server/nodejs/*/bin/node`、nvm、系统路径）和项目目录**，生成 `/etc/systemd/system/mujian.service` 并启用、启动，最后自检端口。用法：

```bash
# 进到项目目录，直接跑（自动查找 server.js 所在目录）
cd /www/wwwroot/mujian
bash deploy/install-service.sh

# 或者手动指定项目目录（项目不在默认查找路径时）
bash deploy/install-service.sh /www/wwwroot/mujian
```

脚本运行时会**交互询问访问口令**：
- 输入一串口令 → 写入项目内 `.env`（`ACCESS_KEY=口令`，权限 600，仅 root 可读），由 systemd 的 `EnvironmentFile` 注入进程环境。用 `.env` 而不是 unit 里的 `Environment=` 直写，是为了避开口令里含 `#`、`$`、空格被 systemd 当注释 / 变量展开而截断的坑。
- 直接回车留空 → 服务完全开放，任何人能读写数据（公网部署不建议）。

> 端口默认 `8910`，写在 unit 的 `Environment=PORT=8910`；要换端口改这一行或启动时用 `PORT=9000 node server.js`。

跑完会打印服务状态、本地自检 `HTTP 200`，以及查看日志的命令。

### 3. 常用命令

```bash
systemctl status mujian        # 看运行状态
journalctl -u mujian -f        # 实时看日志
systemctl restart mujian       # 改了 .env 口令 / 更新了 server.js 后重启
systemctl stop mujian          # 停止
systemctl disable mujian       # 取消开机自启（一般不取消）
```

### 4. 放行端口

- 服务器控制台 → 安全组 / 防火墙：放行 `8910`（TCP）
- 若服务器有 `ufw`：`ufw allow 8910/tcp`

### 5. 打开

浏览器访问：`http://你的服务器IP:8910`
设了口令的话，第一次打开会让你输入（页面本身公开，数据接口才要口令）；任何电脑打开这个地址，看到和编辑的都是同一份数据（服务器 `data/<剧本名>.md`）。

## 常用维护

| 事项 | 做法 |
|---|---|
| 备份全部剧本 | 直接复制整个 `data/` 目录（rsync / scp 走就行），或页面里点 ⬇ 导出备份包 |
| 备份单个剧本 | 只复制 `data/` 下对应的 `<剧本名>.md` 文件即可 |
| 分组数据 | 存在 `data/.groups.json`，和备份一起复制就完整了 |
| 换端口 | 编辑 `/etc/systemd/system/mujian.service` 的 `Environment=PORT=...`，然后 `systemctl daemon-reload && systemctl restart mujian` |
| 改访问口令 | 编辑项目内 `.env` 的 `ACCESS_KEY`，保存后 `systemctl restart mujian`（或用 `install-service.sh` 重跑，会重新询问口令） |
| 忘记口令 | 同上，直接改 `.env` 的 `ACCESS_KEY` 并重启；浏览器若记住了旧口令，刷新页面重新输入新口令 |
| 查看日志 | `journalctl -u mujian -f` |
| 更新前端页面 | 用新版 `console/` 下的四个文件（`index.html`、`style.css`、`app.js`、`boot.js`）整个覆盖旧文件即可，数据不受影响；静态文件直接生效，若浏览器缓存旧 js 强刷一下（Ctrl/Cmd+Shift+R） |
| 更新后端 | 覆盖 `server.js` 后 `systemctl restart mujian` |
| 忘了访问地址 | 服务器 IP 自己查；域名需提前解析 |

## 常见问题

- **打不开 / 连接超时**：先 `systemctl status mujian` 确认是 `active (running)`；再确认安全组放行了对应端口；最后 `curl http://127.0.0.1:8910/` 在服务器本机自测，能通说明服务正常、问题在网络/防火墙。
- **能打开页面但保存失败**：检查 `data/` 目录是否可写（权限 owner 与 unit 里 `User=` 一致，默认 root）、磁盘空间；设了口令的话确认口令正确（401 会被拦）。
- **输入口令提示不正确**：确认 `.env` 里变量名是 `ACCESS_KEY`（全大写）、值和你输入的一致（不含空格）；改完要 `systemctl restart mujian`。
- **想多个设备同时用**：直接支持——多设备都填同一个云端地址，本机先秒显、后台拉最新版，实现共用一份数据；注意别长时间同时改同一剧本不保存（自动保存会覆盖，正常使用无影响）。
- **还想更安全**：配合方案 B 的 HTTPS，或云安全组加 IP 白名单（只允许家里 / 公司的 IP 访问）。
- **install-service.sh 找不到 node / 找不到 server.js**：手动指定项目目录 `bash install-service.sh /你的/项目/目录`；确认 node 已装（命令 `node -v` 能出版本号）。
